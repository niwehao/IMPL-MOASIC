# 24_x4_threepipe — X4:三管 corridor 族修复奇偶盲区(§8.2 收尾之一)

对 23 组"奇偶盲区"发现的直接回应:RAIL2P corridor 族
(`mosaic_schedule.h WIRING_RAIL2P`)把 DIRECT 按 pair 平面拆成
**DIRECT_A(偶 pair)/ DIRECT_B(奇 pair)** 两条 corridor,dst 入口
从"两管+平面耦合"变成**真三管可控**(NV / NIC-A / NIC-B);prior 用
**通用 K-管 greedy waterfilling**(`waterfill_pipes()`,等完成时间注水,
兑现 §4.2 承诺;K=3 用例)。`-mosaic_known_planeb F` = 静态异构已知
(如 B 面为旧代硬件);unknown = 纯 feedback。C=5:{DA,DB,TX,RX,SP}。
拓扑/负载同 23 组。数据 `results.csv`(附 23 组旧族与 FAST 对照列)。

## 结论

1. **X3 的两个失败/薄弱点全部修复**:2400+B/4 从 0.73× 到 1.02×,
   360+B/4 从 0.97× 到 1.05×。修复主要来自 **corridor 结构**(三管可控)
   而非先验知识——强侧 unknown 与 known 几乎无差(6717 vs 6790)。
2. **known prior 的价值随 feedback 变慢而增长**:90+B/4 处 known 比
   unknown 快 22%(23876 vs 30552)——弱 NV 下每波交付慢、探索代价高,
   好初值省掉的学习波次更值钱。这给 §4.2 的 "1/W 遗憾"设计指南提供了
   反向印证。
3. **族选择也是 regime 相关的(如实)**:对称/弱 NV 处旧族(统一 DIRECT
   + 更多 spread lane)仍略优(360 对称 8584 vs 8956;90/B2 21219 vs
   22277)——不对称越重、scale-up 越强,三管拆分的收益越大。与 16 组
   "C 的最优值随 regime 移动"同构,支撑"corridor 族按拓扑+环境生成"。
4. K-管注水在本系统的形态(诚实注记):per-GPU 入口物理管数 ≤ 端口数,
   两层系统里 K>3 的独立管尚未出现;`waterfill_pipes()` 为 X2-full 的
   per-spine 组与未来异构多层 fabric 预留了通用实现。

复现:23 组命令 + `-mosaic_corridors 5 [-mosaic_known_planeb F]`
(RAIL2P 族随 `-topology flex_rail2p` 自动启用)。

## 2026-07-28 重跑注记(32 组挂账处理)

- **本组自身数字全部可复现**:当前代码(f1f5b2a)重跑 C5 九点 + known
  五点,与上表逐位一致(`cache/nonuniform/x32_acct.log` 的 `x4` 行)。
- **但"旧族(23)"对照列已失效**:那一列产生于本组**原地替换掉**的旧
  RAIL2P corridor 族(统一 DIRECT),没有旧族开关,任何已提交版本都跑
  不出 9385/7168 等值(23 组 README 有完整溯源)。因此结论 1 的**幅度**
  "0.73×→1.02×(9385→6717)"不成立;成立的是**方向**:平面拆分族让
  2400+B/4 达到 1.02×,弱 NV 处 known prior 的 22% 价值也不受影响。
- **C=5 不再是该族的最优 corridor 数**:同族 C=6 在 2400/360 六个点全面
  更好(6349/6418/6679 vs 6507/6651/6717;8862/9466/9581 vs
  8956/9629/9918);90 弱 NV 处 C4/C5-known 更好。X4 的贡献应记为
  **corridor 族结构**(DIRECT 按平面拆分 + K-管注水 prior),而不是
  C=5 这一具体配置。
