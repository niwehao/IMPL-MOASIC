# 17_threshold — 波交付阈值为什么取 75%?(问题:threshold 选择依据)

`-mosaic_threshold t`:上一波交付比例达到 t 即测速并放下一波。机制上的
两端失效假设:t 太低 → 每波测量样本太少(λ 更新噪声大)且下一波配额
基于更陈旧的 λ;t 太高 → 波间重叠消失,波尾排空管道(§4.8 v1 的教训)。
负载 hot-dst zipf1.0/seed42,其余参数默认(W=6, γ=0.7)。数据 `results.csv`。

## 主表(completion_us)

| thr | 2400 | 360 | 90 |
|---|---|---|---|
| 0.30 | 3522 | 8305 | 16625 |
| 0.50 | 3730 | **8119** | 16229 |
| 0.60 | 3677 | 8153 | 16404 |
| 0.75(默认) | 3557 | 8566 | 16368 |
| 0.90 | 3751 | 8375 | 16354 |
| 0.95 | 3556 | 8218 | **16008** |

## 结论

1. **全带宽 ≤6%**:threshold 不是敏感旋钮,不存在需要逐点调参的悬崖
   ——这是"0.75 不是精调产物"的直接证据(与 08_param_sensitivity 一致)。
2. 两端失效假设在这个范围内**没有出现**(0.3 与 0.95 都不差):波重叠由
   "threshold 每波只触发一次 + 在途 ≤2 波"的结构保证,阈值只挪动重叠量。
3. 0.75 在三个点上都非最优(但都在最优 1.3~5.5% 内);0.95 弱支配 0.75。
   把 0.75 改成 0.95 的设计迭代验证见 21_design_iter——单独看本表不足以
   改默认值(需跨负载验证)。

复现:同 16 组命令,`-mosaic_threshold {t}`。
