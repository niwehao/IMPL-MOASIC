## 结论(重跑后)

1. **奇偶盲区(结构性发现,不受重跑影响)**:`(s+d)%2` 钉死 + 同轨中继
   形状 ⇒ 一切 i→i 型跨机跳的 GPU id 之和恒为偶数(G=8)⇒ **永远钉在
   A 面**。FAST 三档数字逐位不变(对 B 面降速"意外免疫",但对称时也只
   用一半 fabric——6842 = X1 同点 3541 的 1.93×);MOSAIC 的
   TX/RX/SPREAD 中继类同样被钉 A 面,只有跨轨 DIRECT(奇偶混合)碰
   B 面。结论来自布线代数(`flex_pod_graph.h` 的 `p = (src+dst) % 2`),
   与调度器版本无关。
2. **"2400+B/4 输 FAST 0.73×"作废**:当前族在该点 6679(C6)= 1.02×,
   且**九点全部 ≥ FAST**(1.02×–2.22×)。"缺一个能进 B 面的中继类"的
   诊断只对已删除的旧族成立;X4 的 DIRECT_A/DIRECT_B 拆分正是那一类,
   24 组的方向性主张保留,但"9385→6717 修复"的**幅度**不成立(基线
   本来就不是 9385)。
3. **corridor 数/族随 regime 移动(重跑的新发现)**:强 NV 处 C6 远优于
   C4(2400 对称:6349 vs 9003);弱 NV + 重不对称处反转,**C4 最好**
   (90/B2:22894 vs C6 24598),known prior 的 C5 更好(22277)。
   与 16 组结论同构。
4. ECMP 线性崩溃(100710@B/4)如实呈现;下界注记:聚合 NIC 割在 B/4 处
   很松(假设两平面可自由换用),平面结构化 max-flow 割仍待补。

**流程教训**:corridor 族这类共享结构被原地替换时,历史归档会静默失效。
今后凡替换共享结构:要么留旧行为开关,要么同一提交里重跑受影响归档。
