## 结论

1. **solver 的 pad-to-max 代价随 skew 超线性放大**:α=0.5 时最好的 solver
   (TACCL 4915)只落后 MOSAIC 1.8×——pad 只有 8MB,padding 浪费小;
   α=2.0 时 64MB pad 让三家集体落后 5.8–6.6×,几乎退化到 ECMP 水平
   (TE-CCL 43271 ≈ ECMP 43421)。**skew 越重,离线 uniform 假设越致命**。
2. **在线方法内部:skew 把 crossover 推向强侧**。α≤1.0 时 2400 点两家打平
   (±1%);α=1.5 起 MOSAIC 开始反超(1.04×),α=2.0 达 **1.18×**——
   热点越尖,FAST 的 W6(碎 skew 相位量化)和 W5(无执行期调整)越痛。
3. **弱 scale-up + 重 skew 是 MOSAIC 的最强区**:α=2.0@90 距 cut 下界仅
   +0.4%(37658 vs 37505)——此点上**任何方案的剩余提升空间 <0.4%**,
   同时给了下界紧度的实证(§7 开放项 1 部分关闭)。
4. FAST 在 α=2.0@90 触发默认 ECN(49 次 rate cut,全方案同一套底座):
   backlog 极端时它的静态置换把 64MB pad 级的块硬塞进降速链路,
   100459µs 比 ECMP 慢 2.3×。
