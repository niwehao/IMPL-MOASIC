# flex_cube:机内 cube-mesh + NVLink 速率异构上的 MOSAIC 实测(M2 边界)

v1,2026-07-27。任务:主报告 §7.1 的 M2 断言"无全交叉机内层的拓扑
MOSAIC 不适用",但从未实测。本轮在一个 DGX 形态、机内为 NDv2 式
hybrid cube-mesh、NVLink 速率 400/200/100G 三档混布的新拓扑上给出实测
结论。实验归档:`csg-htsim/experiments/mosaic_x1/29_flex_cube/`
(109 行 results.csv + plot.png,全部数字 validation PASSED、
queue_drops=0)。**所有新代码与旋钮默认关/不影响既有拓扑;flex_rail
主线 8 nv 点 C6 flags-off 逐位复现 21 组权威值(x29_reg.log)。**

## 0. TL;DR

1. **M2 需要改写**:cube-mesh + 异构速率不是"不适用",而是"换一族
   corridor 后照常适用"。新增 `WIRING_CUBE`(corridor 仍是 4+2 类,
   只是重新推导),MOSAIC 在主线混布上 **W16 = 4824µs,比 FAST
   (5402)快 10.7%**,比 ECMP 快 4.5×,三家离线 solver 全部 >2.4×
   慢于 MOSAIC。
2. **胜负分界与 rail 时代同构**:机内带宽稀缺或异构时 MOSAIC 赢
   (50x16 档 FAST 21839 比 ECMP 还慢,MOSAIC 13514,1.70× 领先;
   100x16 档 MOSAIC-R −9.9%);机内同构且富裕时 FAST 的置换结构赢
   (400x16:FAST 3809 vs MOSAIC 4491)——点对点专用链路天然契合
   一对一置换,这是 M2 里真正成立的部分。
3. **新的可迁移杠杆是波数**:W6→W16 在所有异构画像上 −5~10%
   (主线 4824,rot8 5511,seed43 −5.8%,zipf1.5 −5.5%),在同构
   250/400 档反而劣化,在 flex_rail 上同点只 −0.7%——**波数增益
   随机内异构度增长**(细波化解慢链路 head-of-line 与落点 NIC 偏斜)。
4. **一个新设计教训**:relay 走廊的真瓶颈是**落点 NIC(180G)**而非
   cube 链路容量——按链路容量加权的 prior 输给 uniform 初值
   (5357 vs 5268),C=4 单 lane 过度加权直接劣化 35%(7233)。
   修正旋钮 `-mosaic_cube_nic_cap` / `-mosaic_cube_lane_rot` 已落码,
   但两者都是分治型(rot8 劣化),默认关。
5. **MOSAIC-R 的"不铸新割"双门原样迁移成立**:主线混布 spine 门自动
   关(cold 压 taper 会成为新瓶颈),100x16 门开且 −9.9%;门判界
   在 cube 上无需重调。

## 1. 拓扑与建模(topo/flex_cube_graph.h)

- **形态**:H×G(主线 4×8)。机内 = NDv2 hybrid cube-mesh(每 GPU
  度 4,16 边/host,`NDV2_32_CUBE_EDGES` 邻接),每边一条点对点双向
  链路(独立 queue+pipe,0.7µs,egress 端口逐链路 pacing =
  真 NVLink serializer 语义);速率三档由
  `-flex_cube_speeds "400x6,200x6,100x4"` 按边序分配,
  `-flex_cube_mix_rot` 旋转分布,`-flex_cube_full_gbps v` 退化为
  全交叉单速。主线分布下 B_in(GPU 入射链路和)= 1600/1400/1200/
  1200/900/600/600/500 —— 每 GPU 异构,hot dst 落位由 rot 控制。
- **机间**:与 flex_rail 完全相同的 rail 布线(每 GPU 一 NIC 180G、
  同轨 leaf、taper 180、spine 1,25µs 段),scale-out 侧结果与既有
  实验直接可比。
- **机内路由**:任意 pair 一条 pinned 最短路(BFS,tie-break 取
  瓶颈容量最大再字典序),多链路串联为一条 route——与 flex 系列
  switch-as-wire 一致;需要 chunk availability 语义的中继由调度器
  显式发链(与 flex_rail 相同的原则)。
- **solver 侧视图与执行侧同图**(铁律):TE-CCL
  (`teccl_generate_schedule.py` 新增 flex_cube 视图:逐边异构 cube
  链路 + leaf/spine switch 节点)、TACCL(异构机内画像
  `taccl_flex_cube_topo_2mb.json`:逐链路 beta=67×2400/gbps 同源
  换算,padded 用 make_padded_taccl_topo 重标定)。

## 2. 下界扩展(tools/x1_bounds.py)

cube 模式(`--cube-speeds/--cube-full-gbps/--cube-rot`,分布算法与
C++ 完全同源):B1/B3 的 scale-up 管换成逐 GPU 的 B_in(d);B2(每
host NIC 池)不变;新增机内子集割 B5(对每 host 枚举局部子集 S,
出/入向:跨割 cube 链路 + |S|×nic 为容量,S 的全部出/入需求为
流量)。主线混布 zipf1.0/seed42 的绑定项是 **B2=3327µs(hot host
的 8×180G NIC 池)**;rot4/8 把 hot dst 推到弱 B_in 后换 B1 绑定
(3776/4161)——rot 扫描覆盖了两种绑定态。

## 3. MOSAIC 的 cube 走廊族(scheduler/mosaic_schedule.h WIRING_CUBE)

corridor id 布局与 rail 相同(嵌套集与 ramp 机制直接复用):

| id | cube 语义 | 备注 |
|---|---|---|
| DIRECT | s→d 直达(同轨 NIC 或 spine) | 落 NIC(d) |
| RX | s→(n,r) 同轨 NIC → cube 路由 r⇝rd | 落点随 src rail 遍历全部 8 NIC |
| TX | src host 内 cube 换轨 r⇝rd → 同轨 NIC | 落 NIC(d),免 spine |
| SP_k | s→(h,j)→(n,j)→d,j = rd 的第 k 快 cube 邻居(≠r) | 免 spine,末跳单链路,λ_k 对应 d 的一条物理入射链路 |

prior = 每 dst 的 K 管注水(`waterfill_pipes`,26 组已落码的通用
K 管):管 = {NIC} ∪ {每条入射链路},同机流量按 pinned path 末链
钉为固定负载,跨机流量可分;链路 take 加权 relay 走廊。E2/E3/F3b
(rewaterfill、skew_epoch、ramp_cold)全部经 `nv_of(d)=B_in(d)`
迁移到逐 dst 异构容量;E3 的 skew 门与 F3b 的 spine 门公式不变。

## 4. 主结果(zipf1.0/seed42,主线混布,bound 3327µs)

| 方案 | µs | vs bound | 说明 |
|---|---|---|---|
| static_ecmp / basic | 21829.2 | 6.56× | 直达路径钉死,hot NIC 串行 |
| TE-CCL | 14864.8 | 4.47× | ONE_SHOT OPTIMAL(48 epoch),padded 32MB+fill 截断 |
| TACCL | 13243.7 | 3.98× | 异构 cube 画像 OPTIMAL(8.4s!),padded+fill |
| SyCCL | SKIPPED | – | 层级单速 + 机内稀疏网 = 未修 DfsRateAlloc 崩溃(能力表 §2.4),双重不可表达;近似求解会违反"生成/执行同拓扑"铁律 |
| FAST(guard) | 5401.6 | 1.62× | 结构盲但强:机内步是一对一置换 |
| MOSAIC C6(W6 默认) | 5357.1 | 1.61× | flags-off 基线 |
| **MOSAIC C6 W16** | **4824.2** | **1.45×** | cube 推荐;vs FAST **1.12×** |

TACCL 首次在本项目 8.4s 出 OPTIMAL(cube 画像本就是它的看家本领,
稀疏邻接反而缩小 MIP);但 padded 均匀解 + fabric 盲仍使它慢于在线
方案 2.5×。TE-CCL/TACCL 慢的结构原因与 rail 时代相同(pad 税 +
epoch 语义),不是 cube 特有。

### 4.1 速率画像扫描(机内速度相对 NIC 大/小两个方向)

| 画像 | B_in/GPU | bound | FAST | MOSAIC(W6) | 每档最优 MOSAIC |
|---|---|---|---|---|---|
| 50x16 | 200 | 10732 | 21839(2.04×) | 13514(1.26×) | R 12809(1.19×) |
| 100x16 | 400 | 7031 | 10920(1.55×) | 9215(1.31×) | R 8306(1.18×) |
| 250x16 | 1000 | 3456 | 4399(1.27×) | 4917(1.42×) | 4917(W 无增益) |
| mix(主线) | 500–1600 | 3327 | 5402(1.62×) | 5357(1.61×) | W16 4824(1.45×) |
| 400x16 | 1600 | 3327 | 3809(1.15×) | 4491(1.35×) | lane_rot 4135(1.24×) |

- mesh 慢于 NIC(50/100 档)= rail 的 nv90/180 同族:FAST 的机内
  balance 步在慢 mesh 上崩坏(50 档比 ECMP 慢),MOSAIC 的 corridor
  混合 + wave 反馈稳住 1.19–1.31×。
- mesh 快于 NIC(250/400 档)FAST 胜:**M2 的内核在这里**——
  同构点对点网上,一对一置换恰好每步用满每条链路,而 MOSAIC 的
  per-dst λ 无法表达"逐 (src,dst) 配对协调"(M1 同源病灶)。
- 主线混布双方打平(W6)/MOSAIC 胜(W16):异构性惩罚 FAST 的
  均匀假设,恰好抵消其结构优势。

### 4.2 rot 扫描(hot dst 落位 × 绑定割切换)

rot∈{0,4,8,12}:MOSAIC(W16)= 4824/5232/5511/4717,vs bound
1.45/1.39/1.32/1.42;FAST = 5402/5800/5620/5509。rot8(hot 落弱
B_in,B1 绑定)是 MOSAIC 唯一 W6 输 FAST 的 rot 点(6040 vs 5620),
W16 后反超。**hot dst 落位改变绑定割但不翻转结论。**

### 4.3 稳健性

seed43(bound 4048):base 5544 → W16 5224(−5.8%);zipf1.5
(bound 5269):8697 → 8219(−5.5%)。uniform demand(bound 2237):
MOSAIC 2591(1.158×)微胜 FAST 2624,W16 中性(2600)——skew 门
关,与 rail 行为一致。

### 4.4 退化一致性(设计验证)

full-crossbar 单速 v ∈ {50,300} vs flex_rail nv=7v:ECMP **逐位相同**
(21829.2,fabric 侧等价性 sanity 通过)。MOSAIC/FAST 在 full 模式
偏慢(MOSAIC +23%/+36%,FAST +6%/+3%):共享 NV 管允许单对瞬时用满
全管,点对点专用链路把单对 relay 限到 v——是两种物理的真实差异
(NVSwitch vs 直连),不是实现 bug;FAST 差距小同样因为置换结构。
引用退化数字时必须写明这一模型差异。

## 5. 探索与设计反思(对任务"反思设计问题"的回答)

1. **prior 的错误直觉**:cube 上我最初按"链路容量加权 relay 走廊",
   结果输给 uniform 初值,C=4 单 lane 更是 +35% 劣化。机内链路
   400G ≠ 可用 400G——relay 字节先经落点 NIC(180G)。教训与 26/28
   组一脉相承:**corridor 的价值由它引入的"新瓶颈资源"决定,不由
   末跳链路速度决定**。`-mosaic_cube_nic_cap`(min(nic,link) 加权)
   与 `-mosaic_cube_lane_rot`(lane 落点按 src 旋转摊平 NIC)各回收
   1–8%,但 rot8 场景两者皆负(hot 落弱 B_in 时,旋转把字节推上
   100G 链路),故默认关、按需开。
2. **波数与异构度的标度律**(本轮最有用的新知识):W 在 rail 上是
   平台常量(26 组"加波不加速"),在 cube 上是一等杠杆且增益单调
   随异构度上升。机理:per-link 点对点串行化使"一个大 chunk 压在
   慢链路"的代价远高于共享管;细波同时缩小 trust-region 步长,
   修正落点 NIC 偏斜。W 扫描拐点 W16(W24 边界成本反噬)。
   **推荐配置:cube 上 `-mosaic_corridors 6 -mosaic_waves 16`**
   (异构画像);同构画像保持 W6。未合入代码默认值——与
   "W=6 全场统一"的旧原则冲突,列为 open question(见 §7)。
3. **R 机制原样迁移即正确**:两道生成期门(skew / spine 不铸新割)
   在 cube 上自动做出与 rail 相同性质的判断,无需重调 κ。这支持
   28 组沉淀的不变量表述是拓扑无关的。
4. **证伪记录**:E5 hop_progress 在 cube 主线 −2.1%(5244)但与
   nic_cap 组合返贫(5314);W12+R@100x16(8578)不如 R 单独
   (8306)——细波削弱事件锚定的信号。均如实归档。

## 6. 对 M2 的改写建议(回给 report_mosaic_eps.md §7.1)

> M2(旧):无机内层的直连图不适用;corridor 剪枝前提是两层结构。
> M2(新):**直连稀疏图(regular_32 类)仍不适用;但"机内直连图 +
> rail scale-out"的两层形态适用**——corridor 族按 wiring 重新推导
> (X2 论题的又一实例),λ/wave/门机制原样工作。真正的边界缩小为:
> **机内同构且富裕的点对点网上,per-dst λ 输给逐对置换结构 ~15%**
> (M1 的配对协调缺失在点对点物理下被放大)。

## 7. 局限与下一步

- (a) 主线 gap +45%(W16)仍显著大于 rail 时代同绑定态的 +6%
  (nv2400)。TE-CCL 是 padded 解,不能当 oracle;B2 达成需要 8 NIC
  全程满 + 两级(NIC→cube)完美流水,bound 可能不紧。E0-b 式真矩阵
  oracle(TE-CCL 直解非均匀)是标定第一步。
- (b) W16 与 W=6 全场统一原则冲突;"W 随异构度自适应"(如按
  B_in 方差生成期选 W)是自然的下一个机制,不难做门。
- (c) 400x16 上输 FAST 15% = M1(波内配对 permutation coloring)
  在点对点物理下的放大版;M1 翻盘实验在 cube 上收益应更大。
- (d) 只测了 4×8 与 NDv2 邻接;G≠8 的 cube 画像、以及每 host 不同
  混布(打破 host 对称)未做。
- (e) TACCL 8.4s OPTIMAL 提示:cube 稀疏化后离线求解便宜了,
  "TACCL 解异构机内 + MOSAIC 管 fabric"的杂交路线值得一试。
