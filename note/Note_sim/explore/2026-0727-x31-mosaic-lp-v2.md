# MOSAIC-LP v2:FAST 差距归因与 LP-spread 统一(含 NVSwitch)

v1,2026-07-27。承接 `2026-0727-x30-mosaic-lp.md`(30 组,当时 SOTA)。两个
任务:①同构点对点拓扑上 MOSAIC 为什么没收敛到 FAST——找出差距的
物理来源,并在**不检测同构、不感知劣势**的前提下让 MOSAIC 自动收敛
(覆盖所有 FAST 获胜场景,不止同构);②把 LP 推广到 NVSwitch
(flex_rail)机内,验证"LP 只在拿到拓扑时做一次,MOSAIC-LP 统一全部
wiring"。归档:`csg-htsim/experiments/mosaic_x1/31_mosaic_lp_v2/`
(60 行 results.csv,全部 PASSED、queue_drops=0;回归逐位)。

## 0. TL;DR

1. **差距来源找到了,不是"缺一个 LP 求解器",而是一行落点排序**:
   spread lane 的落点按"链路速度降序"选取,同构下速度全相等 →
   退化为按 id 排序 → **所有 pair 的 lane-0 都落同一块 NIC**。
   证据链:full300 只开落点旋转(lane_rot)就 4754→3630,已越过
   FAST(3660);uniform demand 下同样劣化(3009 vs FAST 2344),
   证明与 skew 无关;关反馈更差(6535),证明不是反馈问题。
2. **统一修复 = 把落点分布也交给 LP(jdist)**,经历三次迭代:
   顶点解(每 pair 单轨)在 skew 下制造 per-pair 热点(4906,更差);
   加"多样性下限"(单轨 ≤1/div_k)后构造性 skew 鲁棒(K6:full300
   3554、400x16 3531,**同构点全面反超 FAST**);最终形态 =
   **hot-column LP**:对每个 dst 轨 rd 假设全部源轨单位流同时涌入
   (spread 走廊存在的场景,结构性最坏情形,仍 workload-free),
   NIC 与 dst 侧链路同时计价、ε·距离项保留邻居局部性——同构时
   自然给出均匀 Latin 摊布(≈FAST balance 的结构等价物),异构时
   给容量感知权重。**全程没有任何"是否同构"的分支。**
3. **统一配置(C6+W12+lp_intra+lp_local+jh-spread)在除两点外的全部
   测点 ≥ FAST**:mix 4134.6(vs FAST 1.31×,1.243× bound,全项目
   主线新高)、400x16 1.08×、full300 1.04×、full50 1.20×、100x16
   1.36×、50x16 1.81×、rot4/8/12 1.12/1.02/1.04×。**FAST 仍胜的两点
   如实记录**:250x16 zipf(0.97×)与 uniform-demand 同构(0.95×)
   ——两者同源于 M1(波内逐对置换协调),spread 层解不了。
4. **NVSwitch 侧统一成立但收益小**:同一 jdist 机制在 flex_rail
   星图 LP 下运行,base 上中性偏正(nv90/360/2400 各 −0.2~0.5%);
   与 R 机制组合为负(360:8258 vs R 7970),rail 推荐维持 MOSAIC-R。
   "统一"的含义是**一套代码+一次 LP 覆盖全部 wiring**,不是一个
   配置处处最优。
5. LP 成本保持毫秒级:hot-column 逐 rd LP 8 个共 **~26ms/拓扑**,
   仍然只在拿到拓扑时算一次、每 host 类型一张表。

## 1. 差距归因(诊断先行,x31_diag)

| 实验 | 结果 | 排除/确认 |
|---|---|---|
| full300 + lane_rot | 4754→3630(< FAST 3660) | **确认落点集中是主因** |
| uniform demand @400/full300 | MOSAIC 仍输 FAST(2588/3009 vs 2456/2344) | 与 skew 无关,结构性 |
| full300 + mosaic_static | 6535(更差) | 反馈无罪 |
| 400x16 C2/C3(去 lane) | 4353/4321 vs C6 4491 | lane 集中在拖累 C6 |
| 400x16 lane_rot+W12+lp | 4115(残余 8% vs FAST) | 剩余部分 = M1 |

机理:29 组为异构设计的"lane k = 第 k 快邻居"在同构下按 id 平序,
每个 dst 的所有 pair 把 λ_lane 质量集中到同 3 个(甚至同 1 个)落点
NIC;FAST 的 balance 步在源侧把每个 host→host tile 均摊到 8 轨,
结构上不可能发生这种集中。**差距不是在线 vs 离线,是"摊布的结构
保证"**。

## 2. jdist 机制(为什么三步迭代都必要)

- **两主机中继 LP(v2a)**:全 (r,rd) 单位商品同时活跃、逐商品禁
  {r,rd} 轨,取 NIC 轨边际。顶点最优 = 每 pair 单轨、全局均衡
  (绑定约束 8/nic=0.0444 全画像一致——再次确认 29 组"落点 NIC
  是真瓶颈")。**但单轨指派对 skew 脆弱**:热 pair 的全部 spread
  质量落一块 NIC → full300 4906(比不用还差)。
- **多样性下限(div_k)**:逐商品单轨流量 ≤1/K → 每 pair ≥K 轨,
  skew 鲁棒性由构造保证(不需要知道谁热)。K 单调改善:K1 4906 →
  K4 3816 → K6 3554(full300)。
- **hot-column LP(最终形态,jdist_hot)**:逐 rd 解"全部源轨单位
  流同时涌入 rd"的最小拥塞问题(x[r][j] 落点分布 + dst 侧聚合流),
  NIC 与机内链路同计价,ε·距离偏好邻居。相对 div_k 版的增量:
  **dst 侧链路容量进入定价**(弱 B_in 的 rd 少用慢链路),mix/seed/
  zipf 因此大幅受益(mix stack 4453→4135,seed43 4818→4354,
  zipf1.5 7326→6324)。
- **skew 门**(与 E3/F3b 同一 gate,demand 已知、不是拓扑检测):
  uniform demand 下 jdist 的摊布损失局部性(−4%),门关自动回退
  手工 lane,逐位=base。

运行时(`-mosaic_lp_spread 表`):spread 诸 lane 的发射合并为一类,
按 jdist 权重拆到所有 transit 轨(链 = s→(h,j)→(n,j)→d);λ 仍按
corridor 调总量,ramp/门/波机制全部不动。

### 诚实记录(负结果与边界)

- **rot4/8/12 上统一 stack 不如 30 组各自专配**(rot12 5273 vs
  4293):jh 的"全轨涌入"先验对 hot 落极弱 B_in 的场景仍偏均匀,
  统一配置只保证"处处 ≥ FAST",不保证"处处 ≥ 历史最优"。
  待做:per-rd 先验用该 rd 的 B_in 份额加权(仍 workload-free)。
- **250x16 zipf 与 uniform-demand 同构是 FAST 保留地**(0.95–0.97×):
  残余差距与 lane/LP 无关——FAST 的机内步是逐对一到一置换,波内
  无链路共享;MOSAIC 的 per-dst λ 表达不了跨 dst 的配对协调,即
  v5 报告的 **M1**。M1 翻盘(波内 permutation coloring)是收掉
  最后 3-5% 的正道,本轮未做。
- **rail 上 jdist×R 组合为负**(8258 vs 7970):R 的 rewaterfill 按
  RX/lane 结构重排 λ,与 spread 合并发射的测量语义相互干扰;
  rail 推荐维持 MOSAIC-R(不带 jdist)。

## 4. 对两个问题的回答

**①为什么没收敛到 FAST/怎么自动收敛**:差距 80% 来自 spread 落点的
确定性集中(同构下排序退化),20% 来自 M1。落点集中用 hot-column
jdist LP 修复——同构时 LP 的解自然就是 FAST balance 的均匀摊布,
异构时自然是容量加权,**同一优化问题的两个解,而非两条代码路径**;
"劣势感知"也不存在:jdist 常开(仅 workload skew 门),在它不该
帮忙的地方(rail base)测得中性。收敛结果:除 M1 保留地外全部测点
≥ FAST。

**②LP 能否统一(含 NVSwitch)**:能——同一 `jdist_hot` 工具用
`--nv-gbps` 切星图、`--speeds/--full-gbps` 切 cube,同一运行时旗标
覆盖 WIRING_RAIL/WIRING_CUBE;LP 只在拿到拓扑时跑一次(26ms,每
host 类型一张表)。但"统一机制"≠"统一收益":NVSwitch 的共享管
本来就没有落点集中问题(这正是 29 组发现的 rail/cube 本质差异),
所以 rail 上 LP-spread 只值 −0.2~0.5%,rail 的主角仍是 R 机制。
MOSAIC-LP 家族的完整分工:**lp_intra(机内多路径)+ jdist_hot
(落点摊布)+ λ/wave/R(时间与 workload)**。
