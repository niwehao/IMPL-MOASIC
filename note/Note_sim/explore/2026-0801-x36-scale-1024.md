# 36 组报告:超大规模(n=256→1024)+ per-A2A 构造时间

**日期**:2026-08-01。**任务**:把对比推到 256/512/1024 节点,量化
**每次 A2A 的 schedule 构造时间**(不含拓扑级一次性初始化)在大规模下
成为 overhead 的现象。**LP 系 solver(TE-CCL/TACCL/SyCCL)按声明排除**:约束求解
在数百节点上无法出解(TACCL 32 节点已 11-17min,变量数 ∝ n³;不属
"能比较的"范围)。

## 0. 规模契约与方法学

- **weak scaling**:per-src 总发送量恒定在 32 节点契约值(65,011,712B
  = 31×2MB);per-pair base = `2MB·31/(n−1)`(1024 位向下取整):
  n=256→253952、512→126976、1024→63488。hot-dst zipf α=1.0 seed42,
  同一生成器;padded_pow2 = 16MB(全 n 一致)。
- **拓扑**:flex_rail,hosts = n/8 × 8 GPU/host,nv360/nic180/
  taper180/spine1(主线参数原样放大;fabric 结构性瓶颈随 n 收紧是
  所有方案共享的物理)。
- **构造时间口径(用户定义)**:demand 每次 A2A 都变(MoE),所以
  只计**demand 依赖的、每 collective 必须重跑**的构造:FAST = 完整
  stage/BvN 构建(`fast_plan plan_us`);MOSAIC = waterfilling 先验
  (`mosaic_plan plan_us`,含 corridor 派生,为 MOSAIC 的上界口径)。
- **仿真器加速(为本组实现,全库逐位回归)**:chunk pool `vector`
  →`list`(requeue 从 O(pool) memmove 变 O(1) splice)+ per-epoch
  FIFO 桶索引(min-epoch 选择从 O(pool) 变 O(log);等价性:跨 epoch
  只有最小值参与,等 epoch 内相对序 = 单调票号序 = 原"绝对队尾
  requeue"的等价重述)。n=128 实测 331.7s→134.8s(2.46×)且
  completion **逐位不变**;n=32 全回归电池(mosaic C4/C6/pc、
  fast@360/2400、ecmp)六值逐位复现(8565.57/8418.42/3525.76/
  7939.84/10126.4/3418.8/21829.2)。

| n | LB | MOSAIC C6 | **MOSAIC C6+PC** | FAST | ECMP |

| 256 | 40571 | 46117(1.137×) | **41547(1.024×)** | 默认 FAILED(0.6M drops)→ +4GB **59410**(1.46×) | FAILED(4.9M)→ +4GB 145371(3.58×) |
| 512 | 74180 | 87162(1.175×) | **78977(1.065×)** | FAILED(2.1M)→ +4GB 超时 → **+16GB 107934**(1.46×) | FAILED(19.1M)→ +4GB 287413(3.87×) |
| 1024 | 139139 | SKIPPED(仿真>20min 政策) | SKIPPED(同) | 默认/4GB/16GB 均 SKIPPED(仿真>20min;构造 2.70-3.11s 已测) | FAILED(47.6M)→ **+16GB 557815(4.01×)** |

读数:
1. **MOSAIC+PC 随规模贴界**:1.024×(256)/1.065×(512)——weak
   scaling 下距割界反而比 32 节点主线(+3~5%)更近;PC 相对 C6 的
   增益稳定在 −9.4~9.9%(diag-CoV 门在大 n 下照常开)。
2. **vs FAST(buffer 补偿后)**:256:1.43×、512:**1.37×**;且 FAST
   需要 4GB(256)/16GB(512)fabric buffer 才能完成——**wave =
   implicit flow control 的 25 组发现在大规模复现**:MOSAIC 在默认
   1GB 下零丢包,且给 4/16GB 时数字逐位不变(41547/78977.1,buffer
   中性双重证明);FAST/ECMP 的 permutation/hash 热点把默认 buffer
   直接打爆。
3. n=1024:三方案仿真墙钟均超 20min 政策线(弃);ECMP 完成但
   FAILED(47.6M drops)。**构造时间在 1024 仍完整测得**(§2)——
   被政策弃掉的是包级仿真成本,不是方案本身。

## 2. 构造时间 = 大规模的隐性 overhead

**per-A2A 构造时间**(demand 每次变,必须重跑的部分;EPS 侧实测
`plan_us`,科学计数已还原):

| n | MOSAIC(waterfilling 先验,含 corridor 派生上界) | FAST(stage/BvN 全构建) | 比值 | FAST 构造 / FAST collective |
|---|---|---|---|---|
| 32 | 71.6µs | 1.87ms | 26× | 1.87/10.1 = 0.18(尚可摊销) |
| 256 | 1.30ms | **111.1ms** | 85× | 111.1/59.4 = **1.87×(构造已超 collective 本身!)** |
| 512 | 4.35ms | **1.494s** | 343× | 1494/107.9 = **13.8×** |
| 1024 | 20.3ms | **2.70-3.11s**(两次测量) | 133-153× | collective 未测(仿真弃);唯一 PASSED 锚 = ECMP+16GB 557.8ms,FAST 构造已达其 5.4× |

**结论(用户假设证实并量化)**:FAST 的构造复杂度在大规模上从
"启动开销"变成**每次 A2A 的主导成本**——256 起构造 > collective
本身,512 达 13.8×;MoE 每层每迭代两次 A2A 的场景下这是乘在训练
主循环上的税。MOSAIC 的 per-A2A 构造保持 O(n·C) 的 ms 级(1024 仅
20ms),规模差距 85-343×。

## 3. 局限

1. **n=1024 的 completion 缺失**(三方案):被
   20-min/run 政策弃,原因 = 包级/规划仿真墙钟,非方案本身;构造
   时间与 ECMP 的 FAILED 诊断仍测得。要补齐需仿真器再提速(EPS:
   每包成本仍 ~8µs,下一热点是 per-port 事件与 route 查找)或放宽
   政策。
2. **FAILED 数字只作诊断**(ECMP@512 的 54575 是丢了 19M 包后的
   假完成,不可与 PASSED 比较)——铁律执行。
3. weak-scaling 契约(per-src 恒定)是选择而非唯一;strong scaling
   (per-pair 恒定)下字节数 ∝n² 会让包级仿真在 256 就不可行,
   且 FAST 构造劣势只会更大(其复杂度不随 message 减小)。
