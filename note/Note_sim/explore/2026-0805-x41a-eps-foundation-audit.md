## 0. 一句话结论

EPS 报告 §3 的 **R4——"共享干扰只有跑起来才可测"——把两种未知混为
一谈**:①**自己造成的干扰**(runtime 亲手把每个字节分配到了每条
corridor 的每个资源上,逐字节可记账)与②**外生不确定**(NIC 降速、
prior 过时、ECN 行为——真的要测)。现设计用 per-dst λ-EWMA 学习①+②
的总和,于是:学习信号在非饱和区是自回声、饱和区被删失(→ 三补丁);
跨 dst 耦合信息被 per-dst 分解丢掉(→ E3/PACE/PC/jdist/F2/F3b 整个
补丁族与 MOSAIC-U 的门塔);探索地板成为常付保险费(M3)。**本质改进
= 把①改成显式记账(全局资源账本 + 逐配额 max-工作量水平化),把反馈
缩回它唯一正当的领地②(有效速率校正)**。C6 探针(§2.3)显示现反馈
子系统在主线仅值 +1.1~2.5%,而中段距界 gap +11.4%——学习机器占据了
方案的复杂度预算,却没有触及剩余 gap 的主体。

## 1. 方法:什么算"立足点",怎么检验

立足点 = 报告 §3 设计需求链的前提(R1-R5)+ §4 各机制隐含的分解选择。
检验标准(全部用仓库内已归档实测,不重跑 PASSED 实验):
(a) 该前提被违反时是否产生了系统性的补丁族(补丁塔 = 分解错误的气味);
(b) 该前提支撑的机制的**边际贡献**实测多大。

## 2. 审计发现:中心缺陷(R4 的混淆)与三条证据链

### 2.1 证据链 A:补丁塔——每个"跨 dst"机制都是同一缺失信息的局部补进

per-dst λ 环丢掉的是"我的分配会怎样影响别人的资源"。26-38 组新增的
几乎每个机制都在把这条信息以特例形式搬回来:

| 机制 | 补的是什么全局信息 | 形态 | 结局 |
|---|---|---|---|
| E3 skew_epoch(26) | 列质量的全局排序(热者先行) | 优先级偏移 + skew 门 | 退役(38) |
| E4 份额捐赠(27) | 热 dst 对冷 dst 份额的占用 | 显式抢占 | 被否(fail.md §2.2) |
| F2 deadline 对齐(28) | 各 dst 完成时刻应相等 | epoch 错位 | 证伪 |
| F3b 冷 ramp(28/32) | 冷 dst 的 corridor 占用挤压热者 | 关走廊 + 双门 | 退役 |
| **F6 PACE(32)** | 冷 dst 注入节奏 vs 全局 straggler 进度 | admission + **三道生成期算术门** | 保留(MOSAIC-U) |
| **PC 配对着色(34)** | 波内落点的跨 src 协调(Latin square) | 静态 Z_n 着色 + **三重自动门** | 保留 |
| jdist LP(31) | 热列落点在 lane 间的摊布 | **离线 LP 表** | cube 保留 |
| C=4→6(16/21) | λ 分不开两条 lane 的份额 → 加维度 | λ 维度加密 | v5 默认 |

模式:核心环看不见全局 ⇒ 每发现一类失衡,就造一个带门的机制把该类
信息静态/半静态地喂回去 ⇒ 门与门再冲突(PC×R、PC×lp_spread,
fail.md §2.6/2.8)⇒ 统一方案 = 机制 + 门的塔(diag-CoV ∧ wiring ∧
lp_spread;skew ∧ 2×slack ∧ taper 门)。**补丁塔不是失败——它们都
赢了数字——但它是分解错位的气味**:这些机制补的信息(列质量、落点
摊布、straggler 进度、份额占用)全都是**同一个对象——全局资源负载
账**——的投影,而这个对象 runtime 本来就完整持有。

### 2.2 证据链 B:反馈信号的测量学缺陷(为什么必须打三补丁)

λ 更新 = 按 per-corridor 交付吞吐份额移动(`update_lambda`,
`mosaic_schedule.h:1810`)。作为"corridor 容量"的估计器,它有结构性
缺陷:**非饱和区,测得的份额 ≈ 分配的份额(自回声,零信息);饱和区,
慢 corridor 阈值前零交付(信息以删失形式出现)**;小配额 corridor 的
rate = 小字节/极短窗 ≈ 突发线速(上偏)。§4.4 的三补丁
(censoring/trust region/anti-windup)与 2% floor 各自对付这四张脸:
删失→补丁1;上偏突发→补丁2;残留污染→补丁3;自回声锁死→floor 强制
可测。**四张脸各有一个补丁,说明这是信号的病,不是参数的病**。
对照:**账本的"信号"= 自己的分配记录 + hop 交付回调(两者 runtime
已有,`chunk_delivered` 逐 hop 触发)——无删失、无回声、无突发偏差,
唯一要估计的只剩每资源有效速率**(名义值 ± 外生偏差)。

### 2.3 证据链 C(本文新探针):C6 统一方案下反馈的边际贡献

§6.3 的三分法是 C4 时代数字(强侧 +8%、极弱侧 −2%)。C6 下重测
(zipf1.0/seed42,`-mosaic_static` vs 默认;adaptive 三点与
`21_design_iter` 归档逐位一致,探针合法):

| nv | bound | C6 adaptive | C6 static | 反馈边际 | adaptive 距界 |
|---|---|---|---|---|---|
| 2400 | 3327 | 3525.76(=归档) | 3587.85 | **+1.8%** | +6.0% |
| 360 | 7556 | 8418.42(=归档) | 8625.49 | **+2.5%** | **+11.4%** |
| 90 | 15105 | 16276.9(=归档) | 16449.9 | **+1.1%** | +7.8% |

**读数**:lane 加密(C6)把 C4 时代反馈的大部分收益吃进了静态结构;
当前整套学习机器(λ-EWMA + 三补丁
+ floor + W 纠缠)在主线的边际 ≈ +1~2.5%,而中段距界 gap 仍有
+11.4%。**方案的复杂度在学习上,headroom 却在学习触不到的地方**
(下节归因)。反馈的不可替代价值仍在外生轴:19 组热点降速
1.44-1.50×、§6.5 drift ≤3%、§6.3 坏初值救回——这些恰好都是"有效
速率被外部改变"类,账本设计里保留为速率校正即可。

### 2.5 gap 主体的归因假设(H2 的依据)

Prop 1 明说 prior 只在"两管不与他人共享"时最优;共享修正被全权交给
反馈,而反馈按 §2.2 只能在饱和边缘缓慢感知。跨 dst 的静态失衡例:
两个热 dst 同 rail 时各自的 prior 独立注水,**同一 spine/中继 NV 被
双重预订**,反馈要数个 wave 才能把份额挪开(γ=0.7、trust ×1.5 的
收敛半径),而 collective 一共只有 W=6 个 wave。中段(360-600)正是
"多资源都接近 binding、跨 dst 争用最密"的区间——距界 +9.5~13.4%
(§6.1)与该机理一致。**该归因可证伪**:账本分配若正确,中段距界
应显著收窄(H2);若收窄失败,则 gap 主体在时序/流水线效应,归因
作废(如实回写)。

## 3. 其余立足点体检(哪些是健康的,不动)

| 立足点 | 判定 | 依据 |
|---|---|---|
| R1 时间预算(LP/MIP 出局) | **健康** | 18/36 组:构造 µs-ms vs solver 分钟级,规模化后差距扩大 |
| R2 决策集 O(1)(corridor 剪枝) | **健康**(粒度待改) | 16 组 C=1≡ECMP→C=2 6× 跳变:签名完备性是真实结构;但"类内轮转"粒度不足(jdist/lane 证据)——账本把粒度自然下探到 lane/relay 而不加 λ 维度 |
| R3 好初值必要(prior) | **健康且应扩权** | v4 迭代:prior 是单项最大收益;本提案把 prior 从"每 dst 隔离注水"升格为"全局账本注水"(§4) |
| R5 prior 会过时(要反馈) | **健康但范围缩小** | 反馈只该管外生轴(速率校正);§6.5/19 组是其正当业绩 |
| wave = implicit flow control | **健康,且应解耦** | 37 组 C/W 定律;账本化后 W 只承担流控/流水线职责,不再绑定测量窗与学习节奏(纠缠见 §6.7:W 带宽 10% 里混着三种效应) |
| min-epoch 软优先 | **健康** | straggler 自动抢占是编码顺带送的(§4.5);PC 在其上做相位协调 |
| 对比契约/公平协议 | **健康** | §5.1 十条,无需动 |

**结论**:立足点问题**唯一且集中**——R4 的混淆及其下游(λ 学习 +
per-dst 分解)。不是"全设计推倒",是**换控制核,保留全部验证过的
外围**(corridor 剪枝、wave 流控、min-epoch、PC、PACE、公平协议)。

## 4. 提案:MOSAIC-L(ledger)——全局资源账本 + 逐配额 max-工作量水平化

### 4.1 规则(全部 O(1)/O(C) 每配额,零 solver)

- **账本**:每资源 r ∈ {每 GPU NIC↑/NIC↓、每 GPU NV↑/NV↓、每 rail
  spine 段}(rail 布线 ~5N 个;pod/rail2p 按 wiring 生成)维护
  `outstanding_r`(已分配未过账字节)与 `rate_r`(有效速率,初值
  名义)。分配时全路径资源 `outstanding += bytes`;hop 交付回调
  (`chunk_delivered` 已逐 hop 触发)过账 `-= bytes`。
- **分配**(替换 emit_wave 的 eff_λ 切分):pair (s,d) 的波配额在其
  corridor mask 上做**水平化注水**——反复把下一份字节给"落入后使
  `max_{r∈path} (outstanding_r/rate_r)` 最小"的 corridor(K 管贪心,
  `waterfill_pipes()` 的账本版;lane 选择 = 同类内选 min 负载 lane,
  jdist 的动态化)。
- **速率校正(反馈的新家,唯一保留的测量)**:每资源用 hop 完成
  事件的窗口吞吐 EWMA 校正 `rate_r`(名义值为先验;降速/干扰自动
  显形)。无 λ、无份额、无 censoring/trust/anti-windup/floor。
- **prior 与 runtime 统一**:t=0 空账本时对全 pair 做同一注水 =
  现 waterfilling prior 的严格推广(单 dst 空账本退化为 Prop 1 闭式;
  跨 dst 顺序注水首次让 prior 看见共享——§2.5 的双重预订消失)。
- **保留**:wave 配额纪律(流控/流水线)、epoch 编码、PC(相位协调,
  与体积水平化正交)、PACE 可选(残余时序轴)、corridor mask。

### 4.2 为什么这不是 E4 的复活(fail.md §2.2 的区别)

E4 两个形态都死于**开环预测**:份额捐赠 = 显式抢占破坏收敛;phase
plan = 生成期流体模拟预测完成序,运行期按预测切表。MOSAIC-L 是
**闭环记账**:每次分配读的是"此刻真实的未完成量"(自己的分配记录
− 已过账交付),不预测完成序、不切表、无抢占——账本天然随执行自动
纠偏(交付快的资源 outstanding 掉得快,下一份自然流向别处)。
一句话:预测/重切会乒乓,记账不会。

### 4.3 预期统一(如果 H 成立,哪些机制可退役/涌现)

- M3 探索地板 → 消失(无学习即无探索;uniform+taper 的 3-23% 保险费
  与 4793 次 ECN cut 应归零,H5);
- E3/PACE 的目标 → 大部涌现(冷配额自动避开热资源;残余时序轴保留
  PACE 兼容);
- jdist LP 表(cube)→ 动态化候选(lane 级 min 负载即摊布);
- C=6 的 lane λ 维度 → 不再需要(粒度在分配器里,C 回归"签名完备"
  语义);
- 三补丁 + floor + guard → 全部退役;
- 19 组/漂移/坏初值的反馈业绩 → 由速率校正承接(H4)。
